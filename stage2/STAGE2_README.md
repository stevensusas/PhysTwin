# Overview

This directory contains scripts to generate synthetic data using Simplicits and run the optimization pipeline.

## Files

- `script_generate_fall_synthetic.py`: Generates synthetic data for PhysTwin digital twins falling under gravity only conditions.
- `script_joint_optimize_clean.py`: Trains and validates simplicits object to match provided video (synthetic or real)
- `solver_ours_new.py`: Pytorch implementation of the kaolin simplicits solver

## Usage

### 1. Generate Synthetic Data

Generate synthetic data using the springmass pretrained digital twin (gaussian rendering not tested yet can ignore for now).

```bash
python script_generate_fall_synthetic.py \
  --data_path /media/extra_disk/data/different_types/single_lift_sloth/final_data.pkl \
  --output_path /home/penn-cg-workstation1/yh/4DHOI/PhysTwin/outputs/single_lift_sloth/synthetic_fall.pkl \
  --simulator springmass \
  --num_frames 85 \
  --fall_height 0.1 \
  --render_pointcloud \
  --base_path  /media/extra_disk/data/different_types \
  --case_name single_lift_sloth
```

### 2. Run Optimization

Optimization should be compatible for both synthetic data (w/o boundary constraints) and real data (w/ boundary constraints)

```bash
python script_joint_optimize_clean.py     --data_path /home/penn-cg-workstation1/yh/4DHOI/PhysTwin/outputs/single_lift_sloth/synthetic_fall.pkl      --case_name single_lift_sloth     --base_dir outputs3     --iters 2 --lr 1e-3  

python script_joint_optimize_clean.py     --data_path /media/extra_disk/data/different_types/single_lift_rope/final_data.pkl       --case_name single_lift_sloth     --base_dir outputs3     --iters 2 --lr 1e-3  
```

## Notes

- Stage 2:
- Optimizable: Simplicits Object (LBS Model + Per-point physical parameters (MaterialMLP) + per-point environment parameters (GripMLP, friction))
- We initialize a Simplicits object with initial physical parameters and run the data-free optimization process to obtain a stable handle-based LBS model. Note that we sample a fixed set of curbature points from the initial point cloud, and use KNN on the first frame to bind some of the curbature to hand controller points for defining boundary constraints. For the remaining frames, we will have a fixed set of curbature points that are constrained, with their targets being the position of the correspondinng hand controller point.
- For each optimization iteration, we first freeze LBS model, and optimize physical parameters (MaterialMLP) and optionally environment parameters (i.e. GripMLP which defines the penalty weights for each constrained curbature point, or friction parameters) w.r.t. PhysTwin losses over windowed rollouts, we then freeze the MaterialMLP (and other environment parameters) to optimize the LBS model. This can either be done in the standard data-free setting or supervised using PhysTwin losses.
- The most recent Kaolin library has warpified simplicits for faster inference, however as a result it is not well compatible for optimization since some of the sparse matrix warp operators cut off the gradient chain. As such, we've setup a pytorch solver to mimic kaolin but there might be some bugs here and there, it would help to cross check.
